# 光伏电站运行维护管理平台

面向电站台账、组串阵列、逆变器、汇流箱、跟踪支架、组件清洗、告警处置与发电结算的一体化光伏电站运行维护工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `pv-plant-ops:entries:v2` 这一项，或调用 `resetModule(模块)`。

## 电量计量（关口表）业务规则

电量计量在通用台账之外有一套独立领域服务 `frontend/src/api/meter-service.ts`：

- **抄录一次落定**：本期读数、上期读数、倍率、本期电量、计量状态写在同一笔抄表记录里，
  经 `withTransaction` 多表事务提交；落盘抛错或校验失败都整笔退回，不留残笔。
  每次抄录带幂等令牌，重复提交同一令牌只算一次；同一计量点同一周期只允许一笔。
- **上期读数归档**：复核确认后追加写入归档表（只追加、不更新不删除）；同周期再确认产生
  新版本，旧版本保留。下一回抄录默认取最近周期的最新版本，老数据无归档时回退老抄表单，
  都取不到时要求抄录人手工录入，绝不填 0。
- **倍率版本化**：倍率初版从计量点投运日期补起；只有**本电站的计量专责**能改倍率
  （页面顶栏可切换身份验证）。写入前先校验，改完自动重算未确认电量，已确认/归档电量冻结。
- **复核 → 结算**：确认计量把结果落到发电结算「待核算清单」（`settlementItems`），
  清单项电量与抄表记录恒等，发电结算页和计量页都有「对账校验」。驳回则清单项软移除，
  重抄确认后复用同一条。
- **批量灌档**：CSV 先全量解析+两轮校验（格式/权限/重复点 + 上期值可解析），缺计量点、
  错行会点名到行，有一行不过整批退回；同内容批次有内容指纹，重复提交只认第一次。
- **取不到数重取**：向表计取数失败自动重试 3 次，全失败保留原读数不清零。
- **单据同源与断点续打**：详情面板展示、CSV 下载、打印任务走同一个
  `serializeMeterDocument` 逐行序列化结果和内容指纹；打印任务建立时冻结逐行内容，
  每行送出成功才推进断点，卡纸/断连/手动中断后从断点续打，已送行不重打、不留半包。
- 规则无头校验：`cd frontend && node scripts/meter-check.cjs`（esbuild 即时打包，
  共 22 项断言覆盖上述规则）。
